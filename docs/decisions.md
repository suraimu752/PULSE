# 設計判断

仕様で決まっていない点は、Phase 1 を止めずに推奨案で実装し、ここに残しています。

## 1. ライセンスは GPL-3.0-only、Slint も GPL を選ぶ

- 採用: リポジトリの `LICENSE` はすでに GPL-3.0。Slint 1.19.0 は `GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0` なので、GPL-3.0-only を選ぶ
- 理由: 指示書の第一候補と一致する。ロイヤリティフリー契約の帰属表示（AboutSlint）は、GPL を選んだ場合には適用されない
- 代替: アプリを寛容ライセンスにして Slint のロイヤリティフリーライセンスを使う。コピーレフトにならないが、指示書の第一候補ではない

## 2. UI ツールキットは Slint 1.19.0、描画は femtovg と software の両方

- 採用: `backend-default`、`renderer-femtovg`、`renderer-software`、`accessibility`、`compat-1-18`
- 理由: デスクトップの標準バックエンドを使い、OpenGL が使えない環境ではソフトウェア描画へ落ちられるようにする。スタイルは `fluent`（Windows に近いウィジェット。アイコン資産は同梱しない）
- 代替: software のみ（依存は減るが、アイドル時 CPU が増える可能性がある）。実測は Phase 5
- `system-tray` は使わない。Phase 1 に常駐トレイはない

## 3. Windows API は windows-rs 0.62.2 のみ

- 採用: `windows` クレート。`sysinfo` などは入れない
- 理由: 指示書が Windows API を優先し、依存を最小にするよう求めている
- 代替: `windows-sys` はより薄いが、指示書の windows-rs から外れる

## 4. CPU 使用率の定義

- 採用: 分母は `GetSystemTimes` のカーネル＋ユーザー（アイドルを含む総プロセッサ時間）の増分。分子は、システムならビジー時間（カーネル−アイドル＋ユーザー）、プロセスなら `GetProcessTimes` のカーネル＋ユーザーの増分。100% は全論理プロセッサが使用中
- 理由: Windows 8 以降のタスクマネージャーと同じ「マシン全体で 100%」の正規化になる。プロセス時間の合計（アイドルを含む）がおおよそ 100% になる
- 代替: 壁時計 × 論理プロセッサ数で割る。システム時刻が取れないときの予備としてコードに残してある
- 論理プロセッサ数は `GetActiveProcessorCount(ALL_PROCESSOR_GROUPS)`。失敗時だけ `GetSystemInfo`（現在のプロセッサグループ、最大 64）に落とす
- 最初のサンプル、カウンタの逆行、PID と作成時刻が一致しないプロセスは `Unavailable`（表示は `N/A`）。増分 0 は `0.0%`
- System Idle Process の CPU を `100% - ビジー` で作らない。開けなければその行は `N/A`

## 5. メモリの定義

- 採用: プロセスは `PROCESS_MEMORY_COUNTERS_EX2.PrivateWorkingSetSize`。システムは `GlobalMemoryStatusEx` の `ullTotalPhys - ullAvailPhys`
- 理由: タスクマネージャーのメモリ列に一番近い公開カウンタがプライベートワーキングセット。コミットチャージ（Private Bytes）や共有を含むワーキングセットは、列の意味が変わる
- 代替: ワーキングセット、プライベートバイト。詳細画面を足すときに併記できる
- 既知の差: タスクマネージャーは「アクティブ」プライベートワーキングセットで、非アクティブなプライベートページを含めないことがある。Phase 1 の値はそれより大きいことがある
- この構造体は Windows 11 22H2 の 2023 年 9 月以降の更新が前提。自プロセスでプライベートワーキングセットが 0 かつワーキングセットが大きい場合は、フィールドが埋まっていないとみなして全プロセスのメモリを `N/A` にする。0 を実測として出さない
- 更新間隔は 1 秒。その間は直前の実測を再利用する（0 には戻さない）

## 6. プロセス名と一覧の形

- 採用: Toolhelp の UTF-16 イメージ名をそのまま出す。アプリ単位のグループ化はしない
- 理由: フレンドリ名はバージョンリソースの読み取りが必要で、Phase 1 の範囲を超える。グループ化は Phase 2 以降の表示機能
- 代替: `QueryFullProcessImageName` とバージョン情報。後から列の中身だけ差し替えられる
- PID 0 のイメージ名 `[System Process]` は、表示だけ `System Idle Process` にする。行の捏造ではない
- 親子関係（`th32ParentProcessID`）はスナップショットに残し、ツリー UI はまだ出さない

## 7. 未実装列の契約

- 採用: ディスク、ネットワーク、GPU 3D / Encode / Decode、専用 VRAM、共有 GPU メモリは最初から `Unsupported`
- 理由: 指示書が「計測不能を 0 と表示しない」「Collector を後から足せる」と指定している
- プロセスのディスクとネットワークは累積バイト、GPU 率は Collector が正規化済みの区間値、システム全体のディスクとネットワークはプロセス合計とは別、と `MetricEnricher` に書いた

## 8. 履歴

- 採用: 500 ms ごとに全プロセスの `Snapshot` を 120 個（60 秒）のリングバッファへ入れる。UI へ渡す系列は CPU% とメモリ使用率だけで、右端が最新、左の未充填は欠測（0 ではない）
- 理由: 指示書は全件保持と、表示時のランキング計算を求め、上位 5 件だけの保存を禁止している。Phase 1 のグラフはライブ表示だけで、時点選択は Phase 3
- 代替: 最初からグラフ用の数値だけを保存する。後から過去時点のプロセス上位を復元できないので不採用
- バッファは固定長で、古いスロットを上書きする。サンプル後に文字列を書き換えても、すでに入ったスナップショットは変わらない

## 9. ソート

- 採用: 既定は CPU 降順。名前と PID は昇順が初期方向。`Value` は常に `Unavailable` / `Unsupported` より前。0 は数値として並ぶ
- 理由: `N/A` を降順の先頭に出すと、欠測が大きく見えてしまう

## 10. 権限と終了操作

- 採用: 昇格しない。`PROCESS_QUERY_LIMITED_INFORMATION` のみ。プロセス終了 UI は置かない
- 理由: 通常ユーザーでの起動が原則で、終了は確認 UI が必要な別機能。誤操作を避ける
- 起動時には昇格しない。詳細な CPU 分析の ETW は、利用者が「分析オン」にしたときだけ専用セッション `PULSE-CPU` を開始する。開始できないときも、全体 CPU とプロセス一覧は続ける。ボタンを押したときだけ「管理者として再起動」する。セッションの扱いと計測方式は第 21 節

## 11. 自分の負荷の表示

- 採用: 同じスナップショットから、自分の PID の CPU とメモリをステータス行に出す
- 理由: 別の推定器を置くと、表示値と一覧がずれる。計測と UI の両方を含んだプロセス値であることは UI の「PULSE 自身」で示す
- これは外部からのアイドル測定ではない。0.5% / 50 MB の目標は未達判定をしない

## 12. テーマと素材

- 採用: Segoe UI、左ナビ、独自の文言。Microsoft のアイコン、ロゴ、スクリーンショットの転載はしない
- 左ナビの絵は `ui/app.slint` の矩形で描いた独自図形。Fluent System Icons や Segoe のアセットは含まない
- 表示色は §16。明るい配色だけには固定しない

## 13. バイナリ名と配布

- 採用: クレート名 `pulse`、実行ファイル `PULSE.exe`。Release は作らず、CI が `PULSE-windows-x64` としてアップロードする
- `publish = false`。crates.io へは出さない
- リリースプロファイルはシンボルを剥がすだけ。LTO は CI の時間とメモリを見てまだ付けない

## 14. ローカル時刻

- 採用: ステータスの時刻は Windows の `GetLocalTime`（サンプル公開時の現在時刻）。Windows 以外のテスト表示は UTC と明記する
- 代替: `chrono`。タイムゾーン表示のためだけに依存を増やさない

## 15. スクロールバー、折りたたみナビ、列幅

- 採用: プロセス一覧は `ListView` の仮想化を残し、組み込みの細いバーは隠す。ビューポート右と下に自前のつまみを置く。横方向の内容幅は列幅の合計（`Columns.table`）で、行が 0 件でもヘッダーは横スクロールできる
- 採用: パフォーマンスの資源リストと詳細、左ナビ（はみ出すとき）も同じつまみで縦スクロールする
- 採用: 全列のヘッダー右端をドラッグして幅を変える。最小幅あり。幅の合計が横スクロール範囲になる
- 採用: 左上のハンバーガーでナビをアイコンだけの細いレールに畳む。ラベルは広げたときだけ
- 理由: 枠のない `Flickable` では、広い列セットをスクロールできることが画面から分からなかった。Windows 11 のタスクマネージャーはアイコン列と列幅変更が前提の操作なので、同じ位置に置いた
- 代替: Fluent の `ScrollView` のまま。つまみが 2px で、ホバーするまで見つけにくいので不採用

## 16. 表示テーマと、画面づくりで使った原則

- 採用: 既定は「システム」。Windows では `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme` を読む（0 がダーク、それ以外はライト）。約 2 秒ごとに再読込し、手動のライト / ダーク中は上書きしない。値が読めないとき（Windows 以外、キーが無い）はライト
- 採用: 色は `Theme` にまとめ、サイドバー、表、グラフ、スクロールバー、警告、`N/A`、`未対応` を両方のテーマで描く。ダークは反転ではなく、奥のサイドバー、作業面、浮いたカードの三段
- 画面はタスク用（Operate）。Segoe UI のまま、アクセント色は選択、ソート、実測値、グラフに限る。選択ナビの左端バーは置かない。動きはサイドバーの折りたたみだけ（160ms、ease-out）。行の更新とテーマ切替は即時
- 押した状態をナビ、資源カード、テーマ切替に付ける。空の一覧は一文で示す
- マーケティング用の写真、シェーダー、ヒーロー入場、実在製品アイコンの流用は使わない。アイコンはこれまでどおり自作
- 根拠にした原則は `.cursor/skills/` の impeccable（Operate、コントラスト、余白、スクロールバーをパレットに含める）、emil-design-eng（頻繁な操作は動かさない、ease-out、押下フィードバック）、taste-skill（端を揃え、テンプレート臭を避ける）。Web 専用の検査や CSS の手順は適用しない

## 17. パフォーマンスタブの高さ

- 採用: 左の資源一覧と右の詳細は、親が割り当てた高さだけをビューポートにする。中身の高さではページを伸ばさない。最小ウィンドウは 800×560。グラフの棒は `preferred-width: 0` で幅を奪わない
- 理由: 中身の希望高さに合わせると、CPU グラフがある Windows では下端が窓の外に出て、スクロールバーも出なかった
- デモ: `mock` feature のときだけ `MockProbe` が同じ `RawSample` を出す。UI はデモかどうかを知らず、`DEMO DATA` の表示だけを別に受ける。Release の `cargo build --release` はこの feature を付けない
- グラフのクリックは位置を覚えるだけ。過去時点の再計算は全件履歴が残っている前提で後から足す

## 18. 列と資源の並び、分割

- 採用: プロセスの列はヘッダーを横にドラッグするか、「列」メニューのチェックと上下で並べ替え・非表示にする。名前は消せない。表の横幅は表示中の列だけを足す
- 採用: パフォーマンスの資源も「項目」メニューで同じことをする。表示中が 1 件のときはそれ以上隠さない。選択中を隠したら、並びの次の表示中へ移す
- 採用: 左の資源一覧と右の詳細の境目をドラッグする。左は 180px 以上、右は 260px 以上。窓が狭いときは希望幅をその範囲へ縮める
- 採用: 並びと幅は `%APPDATA%\PULSE\ui.cfg` に書く。Linux では `XDG_CONFIG_HOME/PULSE`、無ければ `~/.config/PULSE`。`PULSE_CONFIG_DIR` があればそこ。ネットワークには出さない
- 理由: 詳細グラフの希望幅がカードの右パディングを越えて、枠がスクロールバーとカードの境界に乗っていた。幅を親の内側に固定し、スクロールバーは枠の外へ出した

## 19. ディスク、ネットワーク、GPU の取得

- 採用: Collector は Process（既存の CPU / メモリ）、Disk、Network、GPU に分ける。一つが失敗しても次を呼ぶ。パニックしてもその Collector だけを外し、他の値は残す
- 採用: プロセスのディスクは `GetProcessIoCounters` の転送バイト増分。物理ディスクは PDH `\PhysicalDisk(*)`。画面のカードは後者。前者を物理転送量とは書かない
- 採用: ネットワークのプロセス帰属はしない。通常ユーザーの `GetIfTable2` でアダプター速度だけ取り、プロセス列は `要管理者`。カーネル ETW は管理者権限が要るため既定では使わない
- 代替: ETW で PID 帰属する。権限と欠測の説明が増え、通常ユーザーの既定に合わないので不採用
- 採用: GPU 使用率はエンジン種別ごとに最大。合計して 100% を超える値は作らない。専用と共有は別。識別子は LUID
- 履歴: リングは全プロセスのスナップショットを 60 秒分持つ。ディスク、ネット、GPU、VRAM もそのスナップショットに入る。終了したプロセスは古い枠に残る。上位 5 件だけは保存しない

## 20. 60 秒グラフの時点選択と上位 5

- 採用: クリックした X を、右端が最新の 60 秒軸の単調時刻にする。その時刻を含む計測区間を選ぶ。区間が無ければ、半区間以内で最も近い実測。同距離は `sequence` が大きい方。空のスロットは隣から借りない。棒の高さから値も順位も補間しない
- 採用: 選択の身元は `sequence` と `Instant`。壁時計は表示だけ。「N 秒前」を身元にしない。新しいサンプルが来ても、選択は別の点へずれない
- 採用: 選択中のスナップショットは、リングとは別に `Arc` を 1 本だけ持つ。リングが捨てたあとも、値と上位 5 を出し続ける。自動ではライブに戻さない。グラフ本体は最新 60 秒のまま。窓の外では縦線を描かず、「選択中：○分○秒前」と窓の外であることを書く。「ライブに戻る」か別の点を選んだとき、その 1 本を解放する
- 採用: ホバーは時刻と値のプレビューだけ。順位を固定するのはクリックだけ
- 採用: 上位 5 は選んだスナップショットだけから計算する。ライブ中は最新。`Unavailable` と `Unsupported` は比較しない。実測の 0 は残す。同点は PID、次に作成時刻。終了済みでも、その時点の枠に残っていれば出す。PID の再利用は別プロセス
- 採用: ディスク順位はプロセス I/O。グラフの物理ディスク合計とはキャプションで区別する。プロセス別ネットワークが `要管理者` のときは順位を作らない。GPU 順位は選択中の LUID だけ。プロセス表の GPU 列は、従来どおりアダプター横断の最大のまま
- 採用: 資源を切り替えても選択は残し、同じスナップショットのその資源を出す。実測が無ければ `N/A`。黙ってライブへ戻さない
- 代替: リングから落ちたら選択を捨ててライブへ戻す。見ている途中で消えるので不採用
- 代替: 60 秒を超える履歴を全部残す。メモリが時間とともに伸びるので不採用。追加で残すのは選択中の 1 点だけ

## 21. 論理プロセッサごとの CPU 時間

比較した公式資料（Microsoft Learn）:

- [EVENT_TRACE_PROPERTIES / StartTrace](https://learn.microsoft.com/windows/win32/api/evntrace/ns-evntrace-event_trace_properties)。`EnableFlags` はシステムロガーか NT Kernel Logger でだけ有効。権限は管理者
- [私有の SystemTraceProvider セッション](https://learn.microsoft.com/windows/win32/etw/configuring-and-starting-a-systemtraceprovider-session)。`EVENT_TRACE_SYSTEM_LOGGER_MODE` と私有のセッション名を使う。`Wnode.Guid` は `SystemTraceControlGuid` にしてはならない。それは `NT Kernel Logger` 専用で、別名と組むと `StartTrace` が `ERROR_INVALID_PARAMETER`（87）を返す
- [CSwitch](https://learn.microsoft.com/windows/win32/etw/cswitch)。スイッチ時刻、入ったスレッド、出たスレッド、論理プロセッサ
- [SampledProfile](https://learn.microsoft.com/windows/win32/etw/sampledprofile)。一定間隔のサンプル。短い実行は取りこぼす
- [Configuring and Starting the SystemTraceProvider Session](https://learn.microsoft.com/windows/win32/etw/configuring-and-starting-a-systemtraceprovider-session)。`NT Kernel Logger` は共有セッションで、他のアプリが使っているものを止めてはならない

採用: コンテキストスイッチ（CSwitch）。ある論理プロセッサの使用率は、そのプロセッサ上で実行した時間 ÷ 区間の長さ × 100。プロセスの割合も同じ分母。全体 CPU（`GetSystemTimes` のビジー ÷ 全プロセッサ時間）とは分母が違う。

理由: 指示は「その CPU の時間 ÷ 区間」であり、サンプル数からの推定ではない。スレッドが CPU を移ったとき、入った側と出た側で別々に積むにはスイッチ時刻が要る。区間をまたぐ実行は、区間境界で切る。サンプリングは短いバーストを落とす。

代替: CPU Sample Profile。オーバーヘッドは下げやすいが、割合が推定になり、移動と区間境界を時刻で割れない。不採用。

オーバーヘッドの抑え方: 既定はオフ。オンのときだけ専用セッションを開始し、イベントスレッドで区間集計し、UI には 500 ms ごとの集計だけを渡す。オフにしたらセッションを止め、高頻度の処理をしない。全体 CPU の式は変えない。

セッション:

- 名前は `PULSE-CPU` だけ。`NT Kernel Logger` は開始も停止もしない
- `StartTraceW` / `ControlTraceW` / `OpenTraceW` / `ProcessTrace`。`LogFileMode` は `EVENT_TRACE_SYSTEM_LOGGER_MODE | EVENT_TRACE_REAL_TIME_MODE`。`LogFileNameOffset` は 0。クロックは QPC（`Wnode.ClientContext = 1`）。`Wnode.Flags` は `WNODE_FLAG_TRACED_GUID`。`Wnode.Guid` は PULSE 専用の GUID で、`SystemTraceControlGuid` ではない。`Wnode.BufferSize` は構造体とセッション名の領域を含む
- フラグは Process、Thread、CSwitch、DPC、Interrupt、NoSysConfig。`EnableTraceEx2` とは混ぜない。バッファは 1 本 64 KB。最小本数は論理プロセッサ数の 2 倍（24 論理なら 48）、最大はその値と 64 の大きい方。FlushTimer は 1 秒
- 失敗した API 名を画面に出す（例: `StartTrace: WIN32_ERROR(87)`）。183（`ERROR_ALREADY_EXISTS`）のときは `PULSE-CPU` だけを止めてから再試行する
- 起動時に同名を `ControlTrace` QUERY する。自分の残りなら STOP してから START する。`ERROR_WMI_INSTANCE_NOT_FOUND` は新規開始。他の名前は触らない
- 正常終了で自分のセッションだけ STOP し、トレースを閉じ、スレッドを join する
- `ERROR_ACCESS_DENIED` は権限不足。他の機能は続ける。画面は「詳細なCPUプロセス分析には管理者権限が必要です」
- 欠測（`EventsLost` の増分）がある区間は全体を `N/A` にする。最初の区間が閉じるまでは `N/A`。0 で埋めない

アイドル、System、DPC、不明:

- スレッド ID 0 または PID 0 はアイドル。順位に入れない
- PID 4（System）は、スレッド開始で身元が付いたときだけ実在のプロセスとして順位に入れる
- DPC / ISR は実行中スレッドの時間から差し引く。どのプロセスにも足さない。opcode は古い `PERFINFO_LOG_TYPE_DPC` (0x14) と `PERFINFO_LOG_TYPE_INTERRUPT` (0x15)。Windows 11 の opcode が違うと差し引けず、実行中スレッドに残る。実機で確認する
- スレッド開始が無く、終了後に同じ TID が再登場した場合は、別プロセスへ推測で付けない。Unknown とし、どのプロセスの時間にも加えない
- 起動時の Toolhelp スレッド一覧は、その時点で見えた身元であり、推測ではない。すでに終了済みの TID は種にしない
- プロセス名は ETW のイメージ文字列ではなく、既存のプロセススナップショット（PID と作成時刻）から付ける。作成時刻が無い時間は、後から別プロセスの時間として確定しない

身元: 内部はプロセッサグループとグループ内番号（ETW の ProcessorIndex を 64 で割った商と余り）。画面の「CPU 0」はその並びの表示順であり、物理コアではない。配列の添字だけを身元にしない。

履歴: 各スナップショットが、グループ、論理番号、区間、使用率、プロセスごとの CPU 時間、計測状態を持つ。30 秒前の CPU 5 の順位は、その枠に記録した時間だけから作る。いまの値では作らない。選択の保持は第 20 節のまま（`Arc` 1 本、時間ではライブに戻さない、「ライブに戻る」か別の点だけ）。全体表示と論理 CPU 表示の切替、CPU の切替では、選んだ時刻を捨てない。カードの見出しをクリックすると CPU だけ選ぶ。グラフの中をクリックすると、その CPU とその時刻の両方を選ぶ。

`GetSystemTimes` の全体使用率と、ETW の論理 CPU 使用率の平均は一致しないことがある。区間の境界が揃わない、DPC をプロセスから外す、欠測で区間を捨てる、アイドルの定義が違う、ためである。イベント時刻と区間の終端は同じ時計に載せる。`PROCESS_TRACE_MODE_RAW_TIMESTAMP` を付け、最初の生スタンプが `QueryPerformanceCounter` に近ければ終端も QPC（`TRACE_LOGFILE_HEADER.PerfFreq` がその周波数と違うときは、実測が QPC に一致した方を優先する）。生スタンプが FILETIME に近ければ終端は `GetSystemTimePreciseAsFileTime`。変換済み FILETIME を QPC の終端で割ると、論理 CPU が 0% か 100% だけになる。ETW の値で全体 CPU を書き換えない。診断行に両方を出す。

画面の診断行（CPU ページ）: 切替、状態、区間あたりのイベント数、欠測、集計時間、UI 更新時間、ETW 平均ビジー、全体 CPU、PULSE 自身の CPU とメモリ。`DEMO` が付く値は模擬であり、ETW の実測ではない。A は分析オフ、B は分析オンかつ全体表示、C は論理 CPU 表示で時刻を固定したとき。アイドル 0.5% 未満と 50 MB 以下は、この環境では測っていないので達成とは書かない。

管理者としての再起動は `ShellExecuteW` の `runas` で、ボタンを押したときだけ。起動時には呼ばない。Linux では実行せず、エラーを返す。
