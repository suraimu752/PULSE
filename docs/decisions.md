# 設計判断

仕様で決まっていない点は、Phase 1 を止めずに推奨案で実装し、ここに残しています。

## 1. ライセンスは GPL-3.0-only、Slint も GPL を選ぶ

- 採用: リポジトリの `LICENSE` はすでに GPL-3.0。Slint 1.19.0 は `GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0` なので、GPL-3.0-only を選ぶ
- 理由: 指示書の第一候補と一致する。ロイヤリティフリー契約の帰属表示（AboutSlint）は、GPL を選んだ場合には適用されない
- 代替: アプリを寛容ライセンスにして Slint のロイヤリティフリーライセンスを使う。コピーレフトにならないが、指示書の第一候補ではない

## 2. UI ツールキットは Slint 1.19.0、描画は femtovg と software の両方

- 採用: `backend-default`、`renderer-femtovg`、`renderer-software`、`accessibility`、`compat-1-18`
- 理由: デスクトップの標準バックエンドを使い、OpenGL が使えない環境ではソフトウェア描画へ落ちられるようにする。スタイルは `fluent`（Windows に近いウィジェット。アイコン資産は同梱しない）
- 代替: software のみ（依存は減るが、アイドル時 CPU が増える可能性がある）。実測は Phase 5
- `system-tray` は使わない。Phase 1 に常駐トレイはない

## 3. Windows API は windows-rs 0.62.2 のみ

- 採用: `windows` クレート。`sysinfo` などは入れない
- 理由: 指示書が Windows API を優先し、依存を最小にするよう求めている
- 代替: `windows-sys` はより薄いが、指示書の windows-rs から外れる

## 4. CPU 使用率の定義

- 採用: 分母は `GetSystemTimes` のカーネル＋ユーザー（アイドルを含む総プロセッサ時間）の増分。分子は、システムならビジー時間（カーネル−アイドル＋ユーザー）、プロセスなら `GetProcessTimes` のカーネル＋ユーザーの増分。100% は全論理プロセッサが使用中
- 理由: Windows 8 以降のタスクマネージャーと同じ「マシン全体で 100%」の正規化になる。プロセス時間の合計（アイドルを含む）がおおよそ 100% になる
- 代替: 壁時計 × 論理プロセッサ数で割る。システム時刻が取れないときの予備としてコードに残してある
- 論理プロセッサ数は `GetActiveProcessorCount(ALL_PROCESSOR_GROUPS)`。失敗時だけ `GetSystemInfo`（現在のプロセッサグループ、最大 64）に落とす
- 最初のサンプル、カウンタの逆行、PID と作成時刻が一致しないプロセスは `Unavailable`（表示は `N/A`）。増分 0 は `0.0%`
- System Idle Process の CPU を `100% - ビジー` で作らない。開けなければその行は `N/A`

## 5. メモリの定義

- 採用: プロセスは `PROCESS_MEMORY_COUNTERS_EX2.PrivateWorkingSetSize`。システムは `GlobalMemoryStatusEx` の `ullTotalPhys - ullAvailPhys`
- 理由: タスクマネージャーのメモリ列に一番近い公開カウンタがプライベートワーキングセット。コミットチャージ（Private Bytes）や共有を含むワーキングセットは、列の意味が変わる
- 代替: ワーキングセット、プライベートバイト。詳細画面を足すときに併記できる
- 既知の差: タスクマネージャーは「アクティブ」プライベートワーキングセットで、非アクティブなプライベートページを含めないことがある。Phase 1 の値はそれより大きいことがある
- この構造体は Windows 11 22H2 の 2023 年 9 月以降の更新が前提。自プロセスでプライベートワーキングセットが 0 かつワーキングセットが大きい場合は、フィールドが埋まっていないとみなして全プロセスのメモリを `N/A` にする。0 を実測として出さない
- 更新間隔は 1 秒。その間は直前の実測を再利用する（0 には戻さない）

## 6. プロセス名と一覧の形

- 採用: Toolhelp の UTF-16 イメージ名をそのまま出す。アプリ単位のグループ化はしない
- 理由: フレンドリ名はバージョンリソースの読み取りが必要で、Phase 1 の範囲を超える。グループ化は Phase 2 以降の表示機能
- 代替: `QueryFullProcessImageName` とバージョン情報。後から列の中身だけ差し替えられる
- PID 0 のイメージ名 `[System Process]` は、表示だけ `System Idle Process` にする。行の捏造ではない
- 親子関係（`th32ParentProcessID`）はスナップショットに残し、ツリー UI はまだ出さない

## 7. 未実装列の契約

- 採用: ディスク、ネットワーク、GPU 3D / Encode / Decode、専用 VRAM、共有 GPU メモリは最初から `Unsupported`
- 理由: 指示書が「計測不能を 0 と表示しない」「Collector を後から足せる」と指定している
- プロセスのディスクとネットワークは累積バイト、GPU 率は Collector が正規化済みの区間値、システム全体のディスクとネットワークはプロセス合計とは別、と `MetricEnricher` に書いた

## 8. 履歴

- 採用: 500 ms ごとに全プロセスの `Snapshot` を 120 個（60 秒）のリングバッファへ入れる。UI へ渡す系列は CPU% とメモリ使用率だけで、右端が最新、左の未充填は欠測（0 ではない）
- 理由: 指示書は全件保持と、表示時のランキング計算を求め、上位 5 件だけの保存を禁止している。Phase 1 のグラフはライブ表示だけで、時点選択は Phase 3
- 代替: 最初からグラフ用の数値だけを保存する。後から過去時点のプロセス上位を復元できないので不採用
- バッファは固定長で、古いスロットを上書きする。サンプル後に文字列を書き換えても、すでに入ったスナップショットは変わらない

## 9. ソート

- 採用: 既定は CPU 降順。名前と PID は昇順が初期方向。`Value` は常に `Unavailable` / `Unsupported` より前。0 は数値として並ぶ
- 理由: `N/A` を降順の先頭に出すと、欠測が大きく見えてしまう

## 10. 権限と終了操作

- 採用: 昇格しない。`PROCESS_QUERY_LIMITED_INFORMATION` のみ。プロセス終了 UI は置かない
- 理由: 通常ユーザーでの起動が原則で、終了は確認 UI が必要な別機能。誤操作を避ける
- ETW セッションは Phase 1 では開始しない。停止し忘れは起きない

## 11. 自分の負荷の表示

- 採用: 同じスナップショットから、自分の PID の CPU とメモリをステータス行に出す
- 理由: 別の推定器を置くと、表示値と一覧がずれる。計測と UI の両方を含んだプロセス値であることは UI の「PULSE 自身」で示す
- これは外部からのアイドル測定ではない。0.5% / 50 MB の目標は未達判定をしない

## 12. テーマと素材

- 採用: Segoe UI、左ナビ、独自の文言。Microsoft のアイコン、ロゴ、スクリーンショットの転載はしない
- 左ナビの絵は `ui/app.slint` の矩形で描いた独自図形。Fluent System Icons や Segoe のアセットは含まない
- 表示色は §16。明るい配色だけには固定しない

## 13. バイナリ名と配布

- 採用: クレート名 `pulse`、実行ファイル `PULSE.exe`。Release は作らず、CI が `PULSE-windows-x64` としてアップロードする
- `publish = false`。crates.io へは出さない
- リリースプロファイルはシンボルを剥がすだけ。LTO は CI の時間とメモリを見てまだ付けない

## 14. ローカル時刻

- 採用: ステータスの時刻は Windows の `GetLocalTime`（サンプル公開時の現在時刻）。Windows 以外のテスト表示は UTC と明記する
- 代替: `chrono`。タイムゾーン表示のためだけに依存を増やさない

## 15. スクロールバー、折りたたみナビ、列幅

- 採用: プロセス一覧は `ListView` の仮想化を残し、組み込みの細いバーは隠す。ビューポート右と下に自前のつまみを置く。横方向の内容幅は列幅の合計（`Columns.table`）で、行が 0 件でもヘッダーは横スクロールできる
- 採用: パフォーマンスの資源リストと詳細、左ナビ（はみ出すとき）も同じつまみで縦スクロールする
- 採用: 全列のヘッダー右端をドラッグして幅を変える。最小幅あり。幅の合計が横スクロール範囲になる
- 採用: 左上のハンバーガーでナビをアイコンだけの細いレールに畳む。ラベルは広げたときだけ
- 理由: 枠のない `Flickable` では、広い列セットをスクロールできることが画面から分からなかった。Windows 11 のタスクマネージャーはアイコン列と列幅変更が前提の操作なので、同じ位置に置いた
- 代替: Fluent の `ScrollView` のまま。つまみが 2px で、ホバーするまで見つけにくいので不採用

## 16. 表示テーマと、画面づくりで使った原則

- 採用: 既定は「システム」。Windows では `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme` を読む（0 がダーク、それ以外はライト）。約 2 秒ごとに再読込し、手動のライト / ダーク中は上書きしない。値が読めないとき（Windows 以外、キーが無い）はライト
- 採用: 色は `Theme` にまとめ、サイドバー、表、グラフ、スクロールバー、警告、`N/A`、`未対応` を両方のテーマで描く。ダークは反転ではなく、奥のサイドバー、作業面、浮いたカードの三段
- 画面はタスク用（Operate）。Segoe UI のまま、アクセント色は選択、ソート、実測値、グラフに限る。選択ナビの左端バーは置かない。動きはサイドバーの折りたたみだけ（160ms、ease-out）。行の更新とテーマ切替は即時
- 押した状態をナビ、資源カード、テーマ切替に付ける。空の一覧は一文で示す
- マーケティング用の写真、シェーダー、ヒーロー入場、実在製品アイコンの流用は使わない。アイコンはこれまでどおり自作
- 根拠にした原則は `.cursor/skills/` の impeccable（Operate、コントラスト、余白、スクロールバーをパレットに含める）、emil-design-eng（頻繁な操作は動かさない、ease-out、押下フィードバック）、taste-skill（端を揃え、テンプレート臭を避ける）。Web 専用の検査や CSS の手順は適用しない
