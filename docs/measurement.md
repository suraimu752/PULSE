# 計測の定義

画面の数値は、この文書の式と Windows API から出しています。式に入らない値は作りません。

## 間隔

| 対象 | 間隔 | 定数 |
| --- | --- | --- |
| プロセス一覧と CPU 時間 | 500 ms | `CPU_SAMPLE_INTERVAL` |
| プロセスメモリ | 1 s | `MEMORY_SAMPLE_INTERVAL` |
| UI がスナップショットを読む | 250 ms | `UI_REFRESH_INTERVAL` |
| 履歴の保持 | 60 s（120 サンプル） | `HISTORY_WINDOW` |

メモリの 1 秒未満の更新では、直前に読めたバイト数をそのまま使います。読めなかった状態を 0 にはしません。

## 欠測の種類

| 内部 | 表示 | 意味 |
| --- | --- | --- |
| `Value(0)` | `0`、`0.0%`、`0 B` | 読めた結果がゼロ |
| `Unavailable` | `N/A` | 権限不足、API 失敗、レートの初回（基準がない）、カウンタの逆行、PID の再利用で同一プロセスとみなせない |
| `Unsupported` | `未対応` | この版の Collector がまだない |

## CPU

### システム

`GetSystemTimes` の FILETIME（100 ns）を累積で持つ。

- `total = kernel + user`（`kernel` はアイドルを含む）
- `busy = (kernel - idle) + user`
- 使用率 = `busy の増分 / total の増分 × 100`
- 0 以上 100 以下に丸める

`total` の増分が取れない場合だけ、予備として `経過時間 × GetActiveProcessorCount(ALL_PROCESSOR_GROUPS)` を分母にする。

### プロセス

`GetProcessTimes` のカーネル＋ユーザー時間の増分を、上と同じ `total` の増分で割る。

単一スレッドが一つの論理プロセッサを埋め続けた場合、8 論理プロセッサのマシンでは約 12.5% になる。これが意図した正規化です。

増分がちょうど 0 なら `0.0%` です。前サンプルがない、作成 FILETIME が違う、カウンタが減った、のいずれかでは `N/A` です。

割り込みや DPC の時間は Windows がプロセス時間に含めないことがあり、その分は System プロセス側に寄ります。Phase 1 はそれを再配分しません。

### 論理プロセッサ

個数は `GetActiveProcessorCount` で、画面の「CPU 0」はその並びの表示順です。物理コアではありません。内部の身元はプロセッサグループとグループ内番号です。アフィニティマスクでは評価しません。

プロセスがその論理プロセッサをどれだけ使ったかは、ETW のコンテキストスイッチから、そのプロセッサ上の実行時間を区間の長さで割ります。全体 CPU の分母（全プロセッサの `GetSystemTimes`）とは別です。複数の論理プロセッサを使ったプロセスは、それぞれに時間を持ちます。アイドルは順位に入れません。プロセスに帰属できない DPC と割り込みは、どのプロセスにも足しません。身元が無い時間は Unknown で、他のプロセスの時間にしません。

この計測は既定でオフです。オンにできない（管理者権限が無い）ときは、全体 CPU はそのまま出します。説明は「管理者として再起動」の横に一度だけ出し、論理 CPU の順位は `N/A` です。使用率を 0 にはしません。最初の区間と、イベント欠測があった区間も順位は `N/A` です。

ETW で出した論理 CPU の平均と、`GetSystemTimes` の全体使用率は、時計と区間と DPC の扱いが違うので一致しないことがあります。全体 CPU の値は ETW で置き換えません。方式の比較は [docs/decisions.md](decisions.md) の第 21 節です。

Windows 上の ETW セッションは、このリポジトリの Linux 開発環境と GitHub Actions では実セッションを張れないため未検証です。診断行の `DEMO` は模擬データです。

## メモリ

### プロセス

`GetProcessMemoryInfo` に `PROCESS_MEMORY_COUNTERS_EX2` を渡し、`PrivateWorkingSetSize` を表示します。

これは常駐しているプライベートページです。次とは違います。

| 値 | 意味 | Phase 1 |
| --- | --- | --- |
| ワーキングセット | 共有ページを含む常駐量 | 使わない |
| プライベートバイト / コミット | 確保した私有メモリ。常駐とは限らない | 使わない |
| アクティブプライベートワーキングセット | タスクマネージャーの「メモリ」列に近い | API の別フィールドとしては取っていない |

Microsoft の文書では、`PrivateWorkingSetSize` は Windows 11 22H2（2023 年 9 月の累積更新以降）または同等の Windows 10 で有効です。自プロセスでこのフィールドが 0 かつ通常のワーキングセットが 1 MiB より大きいときは、OS がフィールドを埋めていないとみなし、メモリ列をすべて `N/A` にします。

### システム

`GlobalMemoryStatusEx` の物理メモリ合計と利用可能量の差です。タスクマネージャーの「使用中」はスタンバイリストの扱いがより細かいため、完全には一致しません。合計が 0、または API が失敗した場合は `N/A` であり、0 バイト使用中とは表示しません。

グラフの縦軸は、この使用量を合計で割った百分率です。

## ディスク

プロセス列は `GetProcessIoCounters` の `ReadTransferCount` と `WriteTransferCount` の増分です。このカウンタはファイル以外の I/O も含みます。物理ディスクの転送量とは呼びません。最初の区間、カウンタの減少、プロセスを開けないときは `N/A` です。0 にはしません。

パフォーマンスのディスクカードは PDH の英語カウンタ `\PhysicalDisk(*)\Disk Read Bytes/sec` と `Disk Write Bytes/sec` です。`_Total` は個別ディスクがあるとき捨て、二重に足しません。PDH を開けない、または最初の収集で値がないときはカードを `N/A` にします。個別ディスクの名前と速度を詳細に出します。

## ネットワーク

通常ユーザーでは `GetIfTable2` で、起動中かつループバックでないアダプターの `InOctets` / `OutOctets` から送受信速度を出します。これはアダプターの転送量です。プロセスに帰属できる速度ではありません。

プロセス列は埋めません。`ProcessNetMode::NeedsAdmin` とし、画面は `要管理者` です。カーネル ETW は PID 帰属の候補ですが、通常は管理者権限が要ります。既定では有効にしません。欠測や権限不足を仮の 0 にしません。カウンタが戻った区間も `N/A` です。

前回のオクテットを保持したまま間隔を空けて 0 B/s と出さないよう、収集は計測間隔（500 ms）ごとに行い、前回が無い区間は速度にしません。

## GPU と VRAM

PDH の英語カウンタを使います。

- `\GPU Engine(*)\Utilization Percentage` を `pid_…_luid_…_engtype_3D|VideoEncode|VideoDecode` に分解する
- 同じプロセス、同じアダプター、同じ種類のエンジンが複数あるときは最大値。種類をまたいで足さない。結果は 0 から 100 に収める
- プロセス列の 1 つのパーセントは、そのプロセスの該当種類の最大値（複数 GPU があっても合計しない）
- アダプターは LUID。システム使用率もアダプター間の最大
- `\GPU Process Memory(*)\Dedicated Usage` と `Shared Usage` はプロセス別。同じプロセスの別 LUID は別プールとして足す。同じ LUID の重複インスタンスは最大だけ取る
- システムの専用 / 共有は `\GPU Adapter Memory(*)` を LUID ごとに最大を取ってから足す。アダプターカウンタが無いとき、専用だけプロセス合計にフォールバックする。共有はプロセス合計にしない（二重計上になる）
- エンジンが一つも無いときは `なし`。カウンタが読めないときは `N/A`。0% や 0 バイトにしない
- GPU Process Memory はドライバによって 0 や遅延、共有分の二重計上が出ることがある。専用と共有は別の値のまま示す

GPU が無い、またはインスタンス名が想定と違う場合、Windows CI の仮想環境では `なし` か `N/A` になり得ます。実機での数値は未検証です。

## プロセスの識別

キーは PID と、`GetProcessTimes` の作成時刻（100 ns）です。作成時刻が取れないときは作成時刻 0 として扱い、そのキーは PID 再利用に弱いことをコード上のコメントとこの節で明示します。終了したプロセスは、すでにリングバッファへ入ったスナップショットの中では名前と値を保持します。ライブ一覧からは消します。

## 履歴

各サンプルは、その時点の全プロセスの CPU、メモリ、ディスク I/O、ネットワーク、GPU、VRAM に加え、論理プロセッサごとの使用率とプロセス別 CPU 時間、計測状態を持ちます。過去の論理 CPU の順位は、その枠に記録した時間だけから作ります。いまの値では作りません。全体表示と論理 CPU 表示を切り替えても、選んだ時刻は残します。プロセスの GPU は、プロセス表に出すアダプター横断の最大に加え、LUID ごとの値も持ちます。120 個を超えると最も古いものを捨てます。終了したプロセスは、入った枠が落ちるまで残ります。上位 5 件だけは保存しません。系列の空欄は欠測であり、0% の棒にはしません。左の空きは、まだ 60 秒分が無いときの余白です。そこは選べません。

詳細グラフの右端が現在、左端が 60 秒前です。棒の上にカーソルを置くと、その時点の時刻と値をプレビューします。順位は変わりません。棒をクリックすると、そのスナップショットを固定します。クリック位置の X を軸上の単調時刻に直し、その時刻を含む計測区間を選びます。区間が重なるときは sequence が大きい方です。区間に入らなければ、半区間以内で最も近い実測です。同距離も sequence が大きい方です。実測が無い隙間は、隣の値で順位を作りません。描いた棒の高さから値を補間しません。

固定した身元は `sequence` と単調時計（`Instant`）です。壁時計はラベル専用です。「何秒前」を身元にしないので、新しいサンプルが来ても選択は別の点へずれません。

リングが 60 秒を超えてその枠を捨てても、選択中の 1 点だけは `Arc` で残します。グラフ本体は最新の 60 秒のままです。選択が窓の外に出たら縦線は描かず、「選択中：○分○秒前」と、窓の外であることを書きます。値と上位 5 はその点のままです。計測とリングの更新は続けます。「ライブに戻る」か、別の点をクリックするまで戻しません。戻したとき、追加で持っていた 1 点は解放します。60 秒を超える履歴をまとめて残すことはしません。

上位 5 は、ライブ中は最新スナップショット、固定中はその 1 点だけです。いまの使用量を過去の順位へ混ぜません。比較するのは実測値だけです。`N/A` と `未対応` は 0 にしません。実測の 0 は実測として残します。5 件に満たなければ、ある分だけ出します。同点は PID、次に作成時刻です。ディスクの順位はプロセス I/O で、グラフの物理ディスク合計とは別です。プロセス別ネットワークが `要管理者` のときは順位を作らず、その旨を出します。GPU の順位は選んだ LUID だけです。別の GPU の値では埋めません。

資源を切り替えても選択は残ります。同じスナップショットの、切り替えた資源を出します。その資源の実測が無ければ `N/A` です。ライブへは戻りません。

## 負荷

アイドル CPU 0.5% 未満とメモリ 50 MB 以下は、測っていないので達成とは書きません。Windows の Collector 負荷は実機で未確認です。GPU カウンタを開けないときは追加の追跡を始めません。論理 CPU の ETW は既定でオフで、オンのときだけ専用セッションを処理します。UI は 250 ms ごとに集計済みスナップショットを読むだけで、イベントごとに描画せず、Windows API も呼びません。

CPU ページの診断行は、分析のオンオフ、区間あたりのイベント数、欠測、集計時間、UI 更新時間、ETW の平均ビジー、全体 CPU、PULSE 自身の CPU とメモリです。A は分析オフ、B は分析オンかつ全体表示、C は論理 CPU 表示で時刻を固定したときです。`DEMO` が付く数字は ETW の実測ではありません。

## 自己負荷

ステータス行の「PULSE 自身」は、一覧と同じサンプルにある自分の PID の値です。CPU は他のプロセスと同じ分母（`GetProcessTimes` の増分 / `GetSystemTimes` の `total` の増分）です。メモリ列はプライベートワーキングセットです。サンプラーと UI の両方を含みます。外部からアイドル CPU を測った結果ではありません。

CPU ページの 2 行目（`自己`。デモでは `DEMO 自己`）は、プロセス列とは別のカウンタです。

| 表示 | 意味 | 0 との区別 |
| --- | --- | --- |
| 計測 | そのサンプルの所要時間。UI の 250 ms とは別 | 計った値 |
| WS | `WorkingSetSize`。共有ページを含む常駐量 | 読めなければ `N/A` |
| プライベート | `PrivateUsage`（プライベートバイト）。常駐とは限らない | 読めなければ `N/A` |
| ハンドル / スレッド | `GetProcessHandleCount` と Toolhelp の `cntThreads` | 読めなければ `N/A`。0 は API が 0 を返したときだけ |
| リング | 最新スナップショットの見積もり × 入っている枠数。上限であり、ワーキングセットそのものではない | 計算結果 |
| ETW上限 | 分析がオフなら `N/A`。オンなら `MaximumBuffers × 64 KiB`。カーネルプールの上限で、プライベートバイトには入らない | オフを 0 とは書かない |
| 台帳 | 残しているスレッド数 / 終了 TID / プロセス名 | 分析オフのあとは 0 |
| PDH再生成 | 硬い失敗が続いてクエリを捨てた回数 | 捨てていなければ 0 |

プロセス列のメモリは、これまでどおりプライベートワーキングセットだけです。ワーキングセットとプライベートバイトは診断にだけ出します。式は変えていません。

名前の文字列はサンプルをまたいで共有します。終了したプロセスの名前は、リングに残っている枠が落ちるまで残ります。PID の再利用は、これまでどおり PID と作成時刻で別プロセスです。

ウィンドウを最小化しているあいだは、モデルとグラフの更新を止めます。計測と 60 秒の履歴は続けます。戻したときは最新を描き、固定した過去の点は残します。

## 実機での測り方

Linux のモックと GitHub Actions では、アイドル CPU とメモリの目標は測れません。次は Windows 11 の `PULSE.exe` で、タスクマネージャーを隣に置いて読む手順です。各条件で、起動直後、2 分後、30 分後の診断 2 行を残してください。ハンドルが増え続けたら、ディスク以下が `N/A` に戻っていないかも見てください。

1. タスクマネージャーのプロセス頁で PULSE を見つけ、CPU、メモリ、ハンドル（詳細タブ）を控える。PULSE の CPU 列は `GetSystemTimes` の total 増分が分母なので、タスクマネージャーのプロセス CPU に近い比較ができます。論理 CPU のパーセントは区間の長さが分母なので、全体 CPU とは比べません。
2. A。分析オフ、プロセスタブ。診断行はパフォーマンスの CPU を一度開くと出ます。全体 CPU と PULSE の CPU、プライベートワーキングセットを見る。
3. B。分析オフのままパフォーマンスへ移す。ディスク、ネットワーク、GPU が `N/A` のまま固まらないこと。PDH再生成が増え続けないこと。
4. C。分析をオンにし、論理 CPU の格子を出す。ETW上限が `N/A` ではなく、24 論理 CPU なら 4.0 MB（64 × 64 KiB）になること。欠測が増えたら、その区間の論理 CPU は `N/A` のままにする。全体 CPU を ETW の平均で置き換えないこと。
5. D。C のままグラフの過去の棒を固定する。新しいサンプルが来ても順位がその点のままであること。ライブに戻すと、その点の保持が消えること。
6. E。ウィンドウを最小化する。2 分後に戻し、グラフが最新まで続き、D で固定した点を戻す前ならまだ固定されていること。最小化中も履歴は進みます。
7. メモリは三つの数字を分けて残す。診断の PULSE メモリ（プライベートワーキングセット）、WS、プライベート。タスクマネージャーの「メモリ」列はアクティブプライベートワーキングセットに近く、どれとも一致しないことがあります。ワーキングセットだけでリークとは呼びません。
8. 目標はアイドル CPU の平均 0.5% 未満、メモリ 50 MB 以下です。分析オンとオフは別々に判定します。この環境では未達とも達成とも書きません。

## タスクマネージャーとの差

式は数字を合わせるために変えていません。差が出る理由は次です。

- 全体 CPU とプロセス CPU は `GetSystemTimes` / `GetProcessTimes` の区間差分。タスクマネージャーも同じ系統ですが、区間の端が揃わないと数ポイントずれます。
- 論理 CPU は ETW のその CPU 上の時間 / 区間長です。全体 CPU の分母ではありません。DPC と割り込みはプロセスに足しません。
- プロセスメモリの列はプライベートワーキングセットです。タスクマネージャーのメモリ列とは定義が違います。
- プロセスのディスクは `GetProcessIoCounters`（ファイル以外も含む）。パフォーマンスのディスクは物理ディスクの PDH です。
- ネットワークはアダプターの `GetIfTable2` です。プロセス別は取っていません。
- GPU はエンジン種別の最大です。合計して 100% を超える値は作りません。ドライバ差で 0 や遅延が出ることがあります。そのときは `N/A` か `なし` のままです。

## 権限で読めないもの

保護されたプロセスなど、`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` に失敗した行は一覧に残り、CPU とメモリは `N/A` です。リリースの `PULSE.exe` は起動前に管理者を求めますが、それでも開けない行を 0 や推定値にはしません。
